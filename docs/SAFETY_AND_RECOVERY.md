# Safety and recovery

**Current status (20 November 2026):** The canonical migration and five-manga data backfill are complete. This page retains the original offline and ReLIFE migration procedures as historical context. For current private management operations, start with [Repository Handbook](REPOSITORY_HANDBOOK.md), [Operations](OPERATIONS.md) and [AGENTS.md](../AGENTS.md). The whole-dataset wipe remains disabled; general private uploads require a new approved revision-guarded plan.

1. Run `scan` before importing; use only media you own or may lawfully store.
2. `manifest` writes to a **new local directory** and refuses overwriting an existing one. Store `ids.json` privately to preserve identity; do not rename source paths without a migration plan. Concurrent imports using the same registry fail closed under an exclusive `.lock` file. IDs are atomically saved **before** the completed bundle becomes visible; a failed bundle rename may reserve IDs without publishing media, which is safe to retry. Inspect stale locks before removing them. For any source-folder rename, follow the [previewed identity migration](IDENTITY_MIGRATION.md), never edit the registry by hand.
3. `manifest` validates the complete staged bundle before publishing it or committing newly assigned identities. Registry inputs must have known series/chapter keys, non-duplicate opaque IDs and safe source keys; invalid or corrupted registries fail closed. Keep verified backups of `ids.json` before manual recovery.
4. `verify` decodes every media asset and compares dimensions, MIME, byte size and SHA-256 against each chapter manifest. An incomplete or mismatched bundle fails closed.
5. `plan-upload` is an offline dry run against a local mock. The local mock does not contact Hugging Face; separately approved private operations now exist. In the mock, `mock-upload` needs `--approve` and the expected revision. Changed existing media, changed catalogue/manifest ordering, modified rights evidence or missing remote records are **conflicts** and must not be silently discarded. The plan reports `metadataConflicts`; mock uploads cannot automatically merge metadata changes, including chapter additions that require catalogue updates. The complete staged snapshot is checksummed before the revision pointer moves.
6. `backup --bundle bundles/demo-1 --output backups/demo-1.zip` creates a full-media ZIP containing every original image, manifest and rights declaration, plus SHA-256 verification index. `check-backup` rereads every entry and verifies integrity.
7. `restore --backup backups/demo-1.zip --destination bundles/restored` only previews. Add `--approve` to restore to a new path. It refuses an existing destination, validates archive member names and verifies restored originals.

**A catalogue-only copy is not a full-media backup.** Local temporary .part download cleanup is implemented with a preview and exact confirmation phrase. There is no bulk dataset reset or irreversible delete command. Single-manga removal is a reversible catalogue de-list that retains media. Recovery from a compromised HF dataset requires a future owner-approved remote protocol with immutable remote or independently stored backups. Never post backups, logs with titles, or rights evidence to public CI artifacts.

### Historical ReLIFE private dataset recovery procedure (completed 2026-11-20)

Before the later successful canonical migration, ReLIFE was uploaded and verified in the legacy layout, but its root `catalogue.json` is not the Manga Library's canonical `data/library.json` envelope. This is a storage-contract defect, not missing source media. The old ReLIFE uploader is retired. Before any migration or additional title upload, run the read-only inventory scanner, establish the pinned private full-revision recovery branch, independently back up all media off-platform, test on a disposable private staging dataset, verify that IDs and SHA-256 hashes are unchanged, and publish canonical `data/library.json` last. The recovery branch is in the same Hugging Face account and therefore does **not** replace the off-platform full backup. Do not expose any backup archives through a public GitHub Actions artefact or commit.

**Outcome:** The canonical migration, four further title uploads and five-title metadata/cover backfill were later verified. The steps above describe past gates, not a current stop-work order. Do not delete preserved legacy files or claim that the historical HF recovery branch is an independent off-platform full-media backup.
