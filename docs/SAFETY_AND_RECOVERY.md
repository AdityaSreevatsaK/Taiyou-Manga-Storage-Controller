# Safety and recovery

1. Run `scan` before importing; use only media you own or may lawfully store.
2. `manifest` writes to a **new local directory** and refuses overwriting an existing one. Store `ids.json` privately to preserve identity; do not rename source paths without a migration plan. Concurrent imports using the same registry fail closed under an exclusive `.lock` file. IDs are atomically saved **before** the completed bundle becomes visible; a failed bundle rename may reserve IDs without publishing media, which is safe to retry. Inspect stale locks before removing them.
3. `manifest` validates the complete staged bundle before publishing it or committing newly assigned identities. Registry inputs must have known series/chapter keys, non-duplicate opaque IDs and safe source keys; invalid or corrupted registries fail closed. Keep verified backups of `ids.json` before manual recovery.
4. `verify` decodes every media asset and compares dimensions, MIME, byte size and SHA-256 against each chapter manifest. An incomplete or mismatched bundle fails closed.
5. `plan-upload` is an offline dry run against a local mock. Real Hugging Face writes are disabled. In the mock, `mock-upload` needs `--approve` and the expected revision. Changed existing media, changed catalogue/manifest ordering, modified rights evidence or missing remote records are **conflicts** and must not be silently discarded. The plan reports `metadataConflicts`; mock uploads cannot automatically merge metadata changes, including chapter additions that require catalogue updates. The complete staged snapshot is checksummed before the revision pointer moves.
6. `backup --bundle bundles/demo-1 --output backups/demo-1.zip` creates a full-media ZIP containing every original image, manifest and rights declaration, plus SHA-256 verification index. `check-backup` rereads every entry and verifies integrity.
7. `restore --backup backups/demo-1.zip --destination bundles/restored` only previews. Add `--approve` to restore to a new path. It refuses an existing destination, validates archive member names and verifies restored originals.

**A catalogue-only copy is not a full-media backup.** Local-cache deletion is separate and not implemented. There is no bulk dataset reset, deletion or replacement command. Recovery from a compromised HF dataset requires a future owner-approved remote protocol with immutable remote or independently stored backups. Never post backups, logs with titles, or rights evidence to public CI artifacts.
