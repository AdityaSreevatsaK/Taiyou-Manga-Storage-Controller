# Roadmap

1. **M1 offline engine**: Windows menu; original synthetic manga; folder/CBZ import; validated image bytes; stable local IDs; candidate manifests; mock upload preview; verified full-media backup and restore; Linux/Windows CI.
2. **M2 security hardening**: source format recipes, **explicit previewed identity remapping after folder moves with guarded approval and backup is implemented**, further multi-process mock fault injection, isolated image decoding, **bounded source-tree depth and filesystem entry enumeration are implemented**, **bounded chapter streaming and CLI quota options are implemented**, restoration provenance, dependency review. **Cross-process identity-registry locking, duplicate-ID validation, pre-publication bundle verification, atomic registry writes, snapshot metadata integrity and CSV chapter-inventory export are implemented**, alongside the existing JSON report; both remain local and private.
3. **M3 owner approvals**: approve real source packaging, private dataset ID, rights evidence and permitted media, cloud layout, retention, backups, revision/transaction model, private reader authentication and cost/quota controls.
4. **M4 gated HF integration**: read-only inventory/manifest retrieval, verified downloads, then separately reviewed incremental uploads with explicit authorisation and revision guards. Never create the dataset implicitly.
5. **M5 reader compatibility**: connect via private backend adapter with authorisation and tested progress preservation. Changes in the Manga Library belong to that repository.
